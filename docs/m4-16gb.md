# Notes from a 16 GB M4 (Stefa008)

This branch is what I run on my **M4 MacBook Pro, 16 GB, macOS 27.2.1**, with CrossOver Wine + D3DMetal 4.0 beta 3, Series X profile, 1280x720 output. It's current `main` plus my open PR, so anyone on a 16 GB Mac can try the same thing.

## What's in it

- `main` at `bf99e728`
- #381: gives up idle host copies of title memory while RAM runs low (without it the copies only grow, and a 16 GB Mac runs out of memory after 10-16 min in the world)

## How I run it

Build (diagnostics, so the memory and frame lines show up in the log):

```
cargo build --release -p victory --features diagnostics --target x86_64-pc-windows-gnullvm
```

Run from `tools/macos`:

```
VICTORY_ALIAS_BUFFERS=0 VICTORY_SMALL_LOOSE_WINDOWS=1 \
VICTORY_FAULT_TRACKING=1 VICTORY_PATCH_MASKED=all VICTORY_DIAGNOSTICS=1 \
VICTORY_NO_HANG_WATCHDOG=1 VICTORY_EVICT_HEAP_UAV=1 VICTORY_SPILL_SHADERS=1 \
VICTORY_READ_STATS=1 VICTORY_OUTPUT=1280x720 MTL_HUD_ENABLED=1 \
./victory.sh run --execute "<path to>/game_scarlett_master.exe" 2>&1 | tee victory-run.log
```

- `VICTORY_ALIAS_BUFFERS=0`: on 16 GB, aliasing on (the default since #322) ended in a Metal out-of-memory after ~8.5 min for me (details on #322).
- `VICTORY_SMALL_LOOSE_WINDOWS=1`: 256 KB windows for title memory outside buffers instead of 4 MB. Cut the loose windows from 3.7 GB to 0.7-1.3 GB.

## What I see in run 27 (where it's at now)

- Memory no longer collapses, but free RAM sits at 15-18% and swap at ~5 GB the whole time.
- Video memory is ~7.3 GB: ~4 GB placed textures + ~3 GB host copies of textures. That's what fills the room the copy release frees.
- Frame rate isn't steady: 13 fps in lighter spots, 1.4-5 fps with 1,000-2,000 draws.
- A busy frame does ~10,500 refreshes (3.7 GB); of the 1.75 GB it checks, 1.5 GB hasn't changed. That's a lot of work for nothing and probably what makes the frame time jump around.
- With small windows #381 gives up and remakes copies a lot (7,400 remade over the run), which costs time too.

## What I'm trying next

The goal for me is a **steady frame rate and RAM use that leaves the system some room** (about 10 GB for the whole game on a 16 GB Mac), not peak fps.

1. Series S profile (`--console series-s` + `VICTORY_UPSCALER=6`, so the title doesn't pick FSR 4, see #172/#247): the title itself should budget less memory.
2. A fixed memory budget for what VIctory adds (copies + host textures) instead of only reacting when RAM is already low.
3. Skipping refreshes of memory that hasn't changed.
